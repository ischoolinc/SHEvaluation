# Proposal

## Why

再次修習的原始成績必須與一般修課相同：有效的修課直接指定總成績直接寫入原始成績。第一版把指定成績也拿去和歷史成績擇優，指定 80、歷史 82 時原始成績變成 82，與一般修課不一致。5.3 重讀成績仍要保留本次有效成績與歷史成績的較高分，不能改讀已被指定值覆蓋的原始成績。

## What Changes

- 指定總成績可解析時，包含 0，原始成績直接採用進位後的指定值，不與歷史成績或課程總成績比較。
- 指定總成績為空白或無法解析時，原始成績改為本次課程總成績與歷史成績的較高分。沒有課程總成績時維持缺值檢查，不把缺值當 0，並清空「修課直接指定總成績」。
- 新增與更新使用同一個方法。重新計算不把本學期原有原始成績當成歷史成績。
- 5.3 再次修習成績維持本次有效成績。重讀成績改為本次有效成績與歷史最高成績的較高分，不再讀取原始成績屬性。兩個及格旗標各自用對應成績判斷。
- 名冊仍只在找得到歷史成績且不計學分不是「是」時建立。不因指定總成績額外新增名冊。
- 不修改一般修課、重修、補修，也不修改產生學習歷程回寫既有 5.3。

## Capabilities

### New Capabilities

- `semester-subject-repeat-original-score`: 計算學期科目成績時，再次修習如何決定原始成績，以及 5.3 再次修習成績與重讀成績。

### Modified Capabilities

- （無。既有 `import-makeup-retake-score` 只規範匯入重補修的驗證與寫回。）

## Impact

- `RepeatSubjectOriginalScore` 與 `WearyDogComputer.FillSemesterSubjectCalcScore` 的兩個再次修習分支。
- 5.3 `RepeatScore`、`RepeatScoreP` 改由共用方法計算。`Score`、`ScoreP` 仍走 `ResolveRetake53Score`。
- 4.4 的 `SaveScores44()` 維持註解。記憶體中的 4.4 重讀成績仍讀原始成績屬性，因此有指定總成績時會跟 5.3 重讀成績不同，但不會入庫。
- 依序執行計算學期科目成績與產生學習歷程時，若該科目有補考成績，產生學習歷程仍可能用「再次修習成績、補考成績、原始成績」重算並覆蓋 5.3 重讀成績。這次只記錄衝突，不改產生學習歷程。
- 驗證方式：更新可執行分數檢查，並編譯 `SmartSchool.Evaluation.HS.csproj`。
