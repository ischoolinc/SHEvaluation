## 4. GradeYear 綁定

```text

```

`BindListView()` 在 `SchoolYear` 之後插入：

```csharp
item.SubItems.Add(

```

## 5. 重新整理 Feature 名稱不一致

原本：

| 位置 | Feature 名稱 |
|---|---|
| `UCStudentRank` 註冊 | `RankDetailContent` |
| `ImportSchoolYearEntryRank` 呼叫 | `SchoolYearEntryRankDetailContent` |

兩邊名稱不同，匯入完成後無法觸發資料項目重新整理。

最終統一為：

```text
RankDetailContent
```

匯入完成後改為：

```csharp
FISCA.Features.Invoke("RankDetailContent");
```

未另外建立第二個 refresh Feature。

## 6. 匯入完成後才重新整理一次

`Features.Invoke("RankDetailContent")` 仍只發生在：

```text
全部列處理完成
    ↓
UpsertSchoolYearEntryRanks 寫入成功
    ↓
寫入應用程式 Log
    ↓
Invoke RankDetailContent 一次
```

未在每一列匯入時觸發 refresh。

寫入失敗或自然鍵重複中止時不會呼叫 refresh。

## 7. BeginInvoke UI 執行緒處理

`UCStudentRank` 註冊的 Feature callback 改為：

- 控制項已 `Disposed` 時直接返回
- `InvokeRequired` 時使用 `BeginInvoke`，非同步排入 UI 執行緒
- 不使用同步 `Invoke()`
- 不在 UI 執行緒直接查詢資料庫
- 不使用 `Thread.Sleep()`
- 不等待 refresh 完成

實際資料載入仍走既有流程：

```text
ReloadData()
    ↓
LoadDataAsync()
    ↓
BackgroundWorker.RunWorkerAsync()
    ↓
GetSchoolYearEntryRanksByStudentID()
    ↓
RunWorkerCompleted
    ↓
BindListView()
```

## 8. 既有保護機制維持

`BackgroundWorker` 非同步載入維持不變。

`_isBusy` 保護維持不變：

```text
Refresh requested
    ↓
BackgroundWorker is idle
    ↓
Start one database query

Another refresh requested while query is running
    ↓
Set _isBusy = true
    ↓
Do not start another concurrent query

Current query completes
    ↓
If _isBusy == true
    ↓
Run one additional query to obtain the latest data
```

## 13. 資料流

```text
rank_override.grade_year
        ↓
GetSchoolYearEntryRanksByStudentID()
        ↓
SchoolYearEntryRankRecord.GradeYear
        ↓
UCStudentRank（不另查年級）
        ↓
StudentRankDetailContext.GradeYear
        ↓
GetStudentRankDetail()
        ↓
grade_year 查詢條件
        ↓
StudentRankDetailData.GradeYear
        ↓
frmStudentRankDetail.BindHeader()
        ↓
lblGradeYearValue
```

## 14. 明細表頭

`frmStudentRankDetail` 表頭由：

```text
學年度
成績類型
成績項目
建立方式
建立時間
批次名稱
```

改為：

```text
學年度
成績年級
成績類型
成績項目
建立方式
建立時間
批次名稱
```

`BindHeader()`：

- 有值：顯示整數文字
- 無值：顯示空白，不轉成 `0`

查詢失敗或無資料時，仍從 `_context.GradeYear` 帶入表頭。

## 15. 明細查詢條件

選定列代表：

```text
學生 + 學年度 + 成績年級 + 成績類型 + 成績項目
```

`GetStudentRankDetail()` 因此加上年級條件，避免同一學年度、不同成績年級的排名明細混在一起。

`GradeYear` 為 `int?`，條件寫法：

- 有值：`AND ro.grade_year = {n}`（整數直接帶入，不拼接使用者字串）
- 無值：`AND ro.grade_year IS NULL`（舊資料／不完整資料）

結果對應沿用既有 `ToNullableInt(row["grade_year"])`。

## 17. 實作過程發現的問題

1. **明細查詢原本只用學年度 + 成績類型 + 成績項目。**  
   同一學生、同一學年度若有不同 `grade_year`，明細會混在一起。本次把年級納入條件。

2. **舊資料可能沒有 `grade_year`。**  
   屬性維持 `int?`。無值時用 `IS NULL`，表頭顯示空白，不顯示 `0`。

3. **年級資料已存在於清單來源，不需在 UI 再查一次。**  
   由 `SchoolYearEntryRankRecord.GradeYear` 傳入 context 即可貫穿整條資料流。
