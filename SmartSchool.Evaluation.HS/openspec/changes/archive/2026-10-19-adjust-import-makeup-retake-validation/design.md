# Design

## Context

見 proposal.md 的 Why。行為契約見 `specs/import-makeup-retake-score/spec.md`。

實際程式是 `ImportExport/ImportMakeupRetakeScore.cs`（.NET Framework 4.8 類別庫 `SmartSchool.Evaluation.HS`）。分支 `Peter`。參考檔 `ImportMakeupRetakeScore(4).cs`、`ImportStudentV2.cs` 不在此儲存庫，不可修改；共用精靈在 `SmartSchool.Core.General.dll`。專案沒有單元測試專案。

目前列驗證與寫入的關係：

```
ValidateRow
  |-- 缺必要欄位 -> 每列直接失敗
  |-- 格式 switch（修課及格標準目前與其他分數共用「空白或數值」）
  |-- 通過後：不可新增科目；補修／重修條件式必填是兩個獨立 if

ImportPackage（同一列）
  |-- 補修是 -> 組 4.3（讀回寫前的修課及格標準）
  |-- 重修成績有值 -> 組 5.2（獨立 if，讀回寫前的修課及格標準）
  |-- 更新既有 Detail
  |     |-- case 原始成績：目前無條件寫回
  |     |-- case 是否補修成績：是時先 hasChanged=false，再寫原始成績與補修年期
  |-- 其後才做自動取得學分（讀更新後的 Detail）
  |-- SaveScores43 / SaveScores52 依補修或重修學年度、學期分組
```

## Goals / Non-Goals

**Goals:**

- 只在 `ImportMakeupRetakeScore.cs` 調整必要欄位、列驗證，以及原始成績是否寫回與 `hasChanged`。
- 讓補修與重修維持兩條獨立流程，並讓已成立的變更不會被補修分支清掉。

**Non-Goals:**

- 不修改共用匯入精靈、DLL、`ImportWizard` 介面，不實作跳頁，不為空白第二頁補假欄位。
- 不改 `SaveScores43`、`SaveScores52` 的方法、呼叫、分組與名冊欄位對應。
- 不改自動／手動取得學分、重修擇優與及格標準截斷。
- 不把名冊及格判斷改成讀 Excel 新修課及格標準。
- 不新增學期科目成績，也不刪除既有的新增防禦路徑。
- 非補修列只忽略 Excel「原始成績」。補修學年度、補修學期在既有欄位寫入分支的行為不改。
- 不新增單元測試專案。

## Decisions

### 1. 修課及格標準只加入必要欄位清單

「修課及格標準」已在 `wizard.ImportableFields`，只加入 `requiredImportFields`，再由既有的 `wizard.RequiredFields.AddRange` 帶上第一頁。不在 `ImportableFields` 再加一次。自動／手動切換只補回「成績年級」「取得學分」，不會移除此欄，因此不必加新的切換邏輯。

從「補考成績、手動調整成績、學年調整成績、修課及格標準、修課補考標準、修課直接指定總成績」那個「空白或數值」case 移除「修課及格標準」，另立一個 case：空白（含空白字元）為「必須填寫」；非數字為「必須填入數字或小數」；小於 0 或大於 100 為「必須介於0到100」。寫入仍走既有 `case "修課及格標準"`。

替代方案是在共用 case 裡加範圍判斷。不採用，因為該 case 仍要允許其他欄位空白，會變成兩套規則擠在同一分支。

### 2. 原始成績的驗證放在格式迴圈之後

「是否補修成績」空白改成「否」發生在格式 switch 內，順序依 `SelectFields`。原始成績若在同一 switch 裡提前判斷，會在空白尚未改成「否」時誤驗。

因此把「原始成績」從與「重修成績」共用的 case 拆出。格式迴圈不再對原始成績做通用檢查。「重修成績」留下「空白或數值」。迴圈結束、空白已視為「否」之後：

- 「是」：原始成績空白則「必須填寫」；無法 `decimal.TryParse` 則「必須填入數字或小數」。不檢查 0 到 100。
- 「否」：不檢查原始成績。

「原始成績」欄位本身仍留在 `requiredImportFields`，缺欄仍由既有的缺欄檢查拒絕。

### 3. 非補修不寫回原始成績，且不清除 hasChanged

`case "原始成績"` 只有在「是否補修成績」為「是」時才 `SetAttribute`。「否」時不改屬性、不改 `hasChanged`。

`case "是否補修成績"` 刪除 `hasChanged = false`。為「是」時仍可寫入原始成績、補修學年度、補修學期；只有值真的不同才設 `hasChanged = true`。兩處在補修為「是」時寫入的是同一個已驗證 Excel 值，先後順序不會改成不同結果。

補修名冊與重修名冊維持兩個獨立 `if`，不改成 `if/else`。

替代方案是只留其中一個寫入點。不採用，因為既有補修流程本來就在「是否補修成績」分支更新原始成績；拿掉任一邊都比「兩處寫同一值」更容易漏更新。

### 4. 學期格式與條件式必填分開

「補修學期」「重修學期」有非空白值時，用 `int.TryParse` 且結果必須是 1 或 2，否則該欄錯誤「必須填入1或2」。此檢查與是否觸發條件式必填無關。空白不在這一關失敗。

`int.TryParse` 接受「01」（值為 1），拒絕「1.0」「1.5」。這沿用既有整數解析，不另做字串比對。

條件式必填維持在格式通過之後：

- 補修為「是」：學年度或學期空白則「補修學年度、補修學期 必填!」。學年度有值但不是整數則只對學年度報「必須是數值」，不要再把學期一起算進同一句。
- 重修成績有值：學年度或學期空白則「重修學年度、重修學期 必填!」。學年度同樣只在自己不是整數時報數值錯誤。

學期已由 1 或 2 的檢查負責，條件式區塊不再對學期重複報「必須是數值」。

### 5. 名冊與取得學分只驗證、不改公式

4.3／5.2 在更新 Detail 之前組資料，及格標準讀既有 `修課及格標準`（無法解析或小於等於 0 則用 60）。Excel 的新修課及格標準要到後面的欄位迴圈才寫入。自動取得學分在欄位迴圈之後，因此看得到新的修課及格標準；非補修列的原始成績則仍是系統舊值。

本變更記錄這個時間差，不調整組名冊的位置或公式。

### 6. 驗證方式

編譯 `SmartSchool.Evaluation.HS.csproj`（Debug）。沒有自動化測試專案，接受測試以人工情境為準，逐項寫進 `匯入重補修成績調整1013.md`。實作一次只做一個 Todo，完成後停下給確認。

## Risks / Trade-offs

- [名冊及格用舊修課及格標準，學期科目回寫用 Excel 新值] → 只記錄，不改公式。若兩者不同，4.3／5.2 的及格結果可能與更新後的科目標準不一致。
- [補修為「是」時原始成績被兩個 case 各寫一次] → 兩次都寫已驗證的同一值；禁止把 `hasChanged` 設回 false。
- [非補修仍可能經「補修學年度」「補修學期」case 寫入這兩個欄位] → 規格只要求忽略原始成績。不要順手改這兩個欄位的寫入。
- [`ImportStudentV2.cs` 不在儲存庫] → 第二頁行為只做人工確認，不開啟或修改共用元件。
- [無法在此環境對真實資料庫跑匯入] → 不把未執行的人工匯入寫成已通過。

## Migration Plan

沒有資料遷移。回復方式是還原 `ImportMakeupRetakeScore.cs`。已匯入的成績不會被程式回復自動改回。

## Open Questions

無。名冊與新修課及格標準的時間差已決定為只記錄、不改公式。
