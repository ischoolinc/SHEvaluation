# 高中產生學習歷程程式邏輯架構整理

## 概述
本文件整理 `StudentLearningHistoryProcessor` 類別的程式邏輯架構，該類別負責處理高中學生的學習歷程成績資料，包含學期成績、補考成績、重修成績、重讀成績等多種成績類型的處理與儲存。

## 主要類別結構

### 1. StudentLearningHistoryProcessor
**位置**: `Process/Wizards/LearningHistory/StudentLearningHistoryProcessor.cs`

**主要職責**:
- 處理學生學習歷程成績資料
- 整合多種成績類型（學期、補考、重修、重讀）
- 協調資料存取層進行資料庫操作

**核心屬性**:
- `_learningHistoryDataAccess`: 資料存取層實例
- `_SchoolYear`, `_Semester`: 當前處理的學年度和學期

## 資料模型結構

### 1. SubjectScoreRec108
**位置**: `Process/Wizards/LearningHistory/SubjectScoreRec108.cs`

**用途**: 學期科目成績記錄，包含完整的成績資訊

**主要屬性**:
- **基本資訊**: `StudentID`, `IDNumber`, `Birthday`
- **課程資訊**: `CourseCode`, `SubjectName`, `SubjectLevel`, `GradeYear`, `Credit`
- **成績資訊**: 
  - `Score` (學期學業成績)
  - `YearScore` (學年學業成績)
  - `ReScore` (補考成績)
  - `ReAScore` (重修成績)
  - `RepeatScore` (重讀成績)
  - `ScScore` (補修成績)
- **狀態標記**: `checkPass`, `CodePass`, `isScScore`
- **備註資訊**: `Name`, `HisClassName`, `HisSeatNo`, `HisStudentNumber`

### 2. SubjectYearScoreRec108N
**位置**: `Process/Wizards/LearningHistory/SubjectYearScoreRec108N.cs`

**用途**: 學年補考成績記錄（進校學年補考專用）

**主要屬性**:
- **學期成績**: `Score1`, `Score2` (第一、二學期原始成績)
- **學分資訊**: `Credit1`, `Credit2` (第一、二學期修課學分)
- **及格標準**: `PassStandard1`, `PassStandard2`
- **補考資訊**: `ReScore` (第一次補考成績)

### 3. JSubjectInfo & JSubjectDetail
**位置**: `Process/Wizards/LearningHistory/JSubjectInfo.cs`, `JSubjectDetail.cs`

**用途**: JSON 格式的學習歷程資料結構，用於資料庫儲存

**JSubjectInfo 屬性**:
- `refStudentID`: 學生ID
- `serialNo`: 序號
- `name`: 名稱
- `schoolYear`, `semester`: 學年度、學期
- `subject`: 科目名稱
- `subjectLevel`: 科目級別
- `detail`: 詳細資料列表

## 資料存取層

### LearningHistoryDataAccess
**位置**: `Process/Wizards/LearningHistory/LearningHistoryDataAccess.cs`

**主要功能**:
- 將 `SubjectScoreRec108` 轉換為 `JSubjectInfo` 格式
- 提供多種 `SaveScores` 方法對應不同的成績類型
- 處理資料庫儲存操作

**主要方法**:
- `SaveScores42()`: 儲存學期成績 (4.2)
- `SaveScores43()`: 儲存補修成績 (4.3)
- `SaveScores44()`: 儲存轉學轉科 (4.4)
- `SaveScores62()`: 儲存學年成績 (6.2)
- `SaveScores63()`: 儲存學年補考成績 (6.3)
- `SaveScores64()`: 儲存其他學年成績 (6.4)

## 4.4 轉學轉科處理機制詳解

### 1. 4.4 是否使用「是否補修成績」判斷？

**答案：是的**，4.4 轉學轉科處理確實會使用「是否補修成績」進行判斷。

### 2. 4.4 補修處理規則

#### **補修標記設定**
```csharp
// 在 4.4 轉學轉科處理中，同樣會檢查「是否補修成績」
ssr.isScScore = false;  // 預設為非補修
ssr.ScScoreType = "3";  // 補考方式預設 3，專班辦理

if (Utility.GetAttribute(elmScore, "是否補修成績") != null)
{
    if (Utility.GetAttribute(elmScore, "是否補修成績") == "是")
    {
        ssr.isScScore = true;  // 標記為補修成績
    }
}
```

#### **補修學年度學期判斷規則**
```csharp
// 4.4 轉學轉科的特殊處理邏輯
if (ssr.isScScore)
{
    // 如果有勾「是否補修成績」，那補修學年度、學期和畫面上「不同」才會填入
    // 相同的話會在補修成績工作頁處理
    if (!(Utility.GetAttribute(elmScore, "補修學年度") == _SchoolYear.ToString() && 
          Utility.GetAttribute(elmScore, "補修學期") == _Semester.ToString()))
    {
        SubjectScoreRec108OtherList.Add(ssr);  // 加入轉學轉科列表
    }
}
else
{
    // 沒有勾「是否補修成績」，就直接填入
    SubjectScoreRec108OtherList.Add(ssr);
}
```

### 3. 4.4 與其他格式的差異

#### **4.2 學期成績 vs 4.4 轉學轉科**
- **4.2**: 跳過所有補修成績 (`if (ssr.isScScore) continue;`)
- **4.4**: 處理補修成績，但有學年度學期限制

#### **4.3 補修成績 vs 4.4 轉學轉科**
- **4.3**: 專門處理補修成績 (`if (ssr.isScScore)`)
- **4.4**: 處理轉學轉科，包含補修成績的特殊情況

### 4. 4.4 補修處理的關鍵規則

1. **標記規則**: 同樣透過 XML 屬性 `是否補修成績` 來判斷
2. **學年度規則**: 補修學年度學期與當前處理學年度學期**不同**時，才加入 4.4 處理
3. **相同學年度規則**: 補修學年度學期與當前處理學年度學期**相同**時，會在補修成績工作頁處理（不進入 4.4）
4. **非補修規則**: 沒有勾「是否補修成績」的成績，直接加入 4.4 處理

### 5. 4.4 儲存格式

4.4 轉學轉科成績使用以下格式儲存：
- `4.4.1`: 身分證號
- `4.4.2`: 出生日期
- `4.4.3`: 對應學年度
- `4.4.4`: 對應學期
- `4.4.5`: 課程代碼
- `4.4.6`: 科目名稱
- `4.4.7`: 對應年級
- `4.4.8`: 修課學分
- `4.4.9`: 身分別
- `4.4.10`: **抵免後成績**
- `4.4.11`: 成績及格
- `4.4.12`: 是否採計學分
- `4.4.13`: 質性文字描述

### 6. 4.4 補修處理流程

```
1. 讀取轉學轉科成績資料
   ↓
2. 檢查「是否補修成績」屬性
   ↓
3. 設定 isScScore 標記
   ↓
4. 根據補修標記和學年度判斷：
   - isScScore = true 且 補修學年度學期 ≠ 當前學年度學期 → 加入 4.4
   - isScScore = true 且 補修學年度學期 = 當前學年度學期 → 跳過（在補修工作頁處理）
   - isScScore = false → 直接加入 4.4
   ↓
5. 儲存為 4.4 轉學轉科格式
```

### 7. 總結

4.4 轉學轉科處理確實會使用「是否補修成績」進行判斷，主要用於：

1. **識別補修成績**: 透過 `是否補修成績` 屬性標記補修成績
2. **學年度分流**: 根據補修學年度學期與當前處理學年度學期的關係，決定是否進入 4.4 處理
3. **避免重複處理**: 相同學年度學期的補修成績不會進入 4.4，而是在補修工作頁處理
4. **轉學轉科整合**: 將不同學年度學期的補修成績整合到轉學轉科處理中

這個設計確保了補修成績能夠根據其學年度學期屬性，正確地分流到適當的處理流程中。

## 補修處理機制詳解

### 1. 補修標記機制

程式使用 `isScScore` 屬性來標記是否為補修成績：

```csharp
// 檢查 XML 屬性中的「是否補修成績」
if (Utility.GetAttribute(elmScore, "是否補修成績") != null)
{
    if (Utility.GetAttribute(elmScore, "是否補修成績") == "是")
    {
        ssr.isScScore = true;  // 標記為補修成績
    }
}
```

### 2. 補修成績的分流處理

#### **一般學期成績處理 (4.2)**
```csharp
// 在 SaveScores42 中，跳過補修成績
if (ssr.isScScore)
    continue;  // 補修成績不在學期成績中處理
```

#### **補修成績專用處理 (4.3)**
```csharp
// 在 SaveScores43 中，專門處理補修成績
if (ssr.isScScore)
{
    var jInfo = CreateJSubjectInfo(ssr, "4.3", "補修成績", SchoolYear, Semester);
    // 建立補修成績專用的詳細資料
}
```

### 3. 補修學年度學期的特殊邏輯

程式有特殊的補修學年度學期判斷邏輯：

```csharp
// 如果有勾「是否補修成績」，那補修學年度、學期和畫面上「不同」才會填入
// 相同的話會在補修成績工作頁處理
if (ssr.isScScore)
{
    if (!(Utility.GetAttribute(elmScore, "補修學年度") == _SchoolYear.ToString() && 
          Utility.GetAttribute(elmScore, "補修學期") == _Semester.ToString()))
    {
        SubjectScoreRec108OtherList.Add(ssr);  // 加入轉學轉科列表
    }
}
else
{
    // 沒有勾「是否補修成績」，就直接填入
    SubjectScoreRec108OtherList.Add(ssr);
}
```

### 4. 補修資料的比對機制

程式會從學習歷程資料表中取得補修資料進行比對：

```csharp
// 取得有補修資料的學期成績
Dictionary<string, List<SubjectScoreRec108>> dataValue43 = 
    GetLearningHistoryReScoreDataAsDictionary43(_SchoolYear, _Semester, studentIDList);
Dictionary<string, List<SubjectScoreRec108>> semsScore43 = 
    GetStudentScoreDataAsDictionary43(dataValue43.Keys.ToList());
```

### 5. 補修成績的儲存格式

補修成績使用 4.3 格式儲存，包含以下欄位：
- `4.3.1`: 身分證號
- `4.3.2`: 出生日期  
- `4.3.3`: 應修課學年度
- `4.3.4`: 應修課學期
- `4.3.5`: 課程代碼
- `4.3.6`: 科目名稱
- `4.3.7`: 開課年級
- `4.3.8`: 修課學分
- `4.3.9`: **補修成績**
- `4.3.10`: **補修及格**
- `4.3.11`: 補考成績
- `4.3.12`: 補考及格
- `4.3.13`: **補修方式**

### 6. 補修處理的關鍵規則

1. **標記規則**: 透過 XML 屬性 `是否補修成績` 來判斷
2. **分流規則**: 補修成績不進入一般學期成績 (4.2)，而是進入補修成績 (4.3)
3. **學年度規則**: 補修學年度學期與當前處理學年度學期不同時，才加入轉學轉科處理
4. **比對規則**: 補修資料會與學期成績進行比對，確保資料一致性
5. **儲存規則**: 補修成績使用專門的 4.3 格式儲存

### 7. 補修處理流程

```
1. 讀取學期成績資料
   ↓
2. 檢查「是否補修成績」屬性
   ↓
3. 設定 isScScore 標記
   ↓
4. 根據標記分流處理：
   - isScScore = true → 補修成績處理 (4.3)
   - isScScore = false → 一般成績處理 (4.2)
   ↓
5. 檢查補修學年度學期
   ↓
6. 決定是否加入轉學轉科處理
   ↓
7. 儲存到對應的學習歷程格式
```

5. **錯誤處理**: 完整的例外處理和資料驗證機制
