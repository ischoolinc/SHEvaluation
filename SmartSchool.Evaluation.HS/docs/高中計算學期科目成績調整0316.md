# 高中計算學期科目成績調整 0316

## 一、問題描述

在 `FillSemesterSubjectCalcScore` 內：

1. **修課及格標準** 沒有在「更新既有學期科目成績」或部分「新增成績」分支中一致寫入，僅在 `studentFinalScoreDict` 有資料時才寫入，導致更新模式下使用者修改修課的及格標準後重算，Subject XML 不會同步更新。
2. **修課補考標準** 同樣僅在部分分支、且僅在 `studentFinalScoreDict` 有資料時寫入；若 DB 的 `makeup_standard` 改為空，程式未覆寫時會殘留舊值。

後續「是否取得學分」、`ScoreP`、`RepeatScoreP`、`ReScoreP`、`ReAScoreP` 等判斷會讀取 XML 的修課及格/補考標準，若未先寫入最新值，可能用到舊資料。

## 二、原因分析

- 及格標準與補考標準的寫入分散在多處，且多數寫在 `if (studentFinalScoreDict.ContainsKey(...))` 區塊內，未進入該區塊時就不會更新。
- 補考標準未像及格標準一樣有獨立的 Dictionary 整理，也未在 `dtFinalScore` 迴圈中統一整理。
- 沒有共用的「有效及格標準 / 有效補考標準」與「統一寫入屬性」的 helper，導致 fallback（applyLimit、60、空字串）與寫入時機不一致。

## 三、修改方式

### 3.1 資料來源與字典

- **及格標準**：沿用既有 `studentPassScoreDict`（key: student_id, inner key: subject_level），並沿用既有 `applyLimit`（年級對應及格標準）。
- **補考標準**：新增 `studentMakeupScoreDict`（型別 `Dictionary<string, Dictionary<string, decimal?>>`），在 `dtFinalScore` 迴圈中與 `studentPassScoreDict` 一併整理；有數字存 `decimal`，沒設定存 `null`。

### 3.2 共用方法（WearyDogComputer.cs）

1. **GetEffectivePassingStandard**  
   依序：`studentPassScoreDict[studentId][key]` 有值且 ≠ -1 → `applyLimit[gradeYear]` → 60。

2. **GetEffectiveMakeupStandard**  
   有值回傳該值，沒值回傳 `null`（不硬塞 60）。

3. **SetPassingStandardAttribute**  
   對 `XmlElement` 統一寫入「修課及格標準」（經 `GetRoundScore` 處理）。

4. **SetMakeupStandardAttribute**  
   有值寫數字，無值寫空字串，避免殘留舊值。

5. **ApplyCourseStandards**（優化版新增）  
   一次呼叫取得有效及格/補考標準並寫入兩個屬性，減少重複程式碼；各分支改為先呼叫此方法，再做原始成績／是否取得學分／ScoreP 等判斷。

### 3.3 各分支調整（優化：統一用 ApplyCourseStandards + GetEffectivePassingStandard）

- **再次修習 → 更新既有成績**：課程基本資料後立即呼叫 `ApplyCourseStandards(...)`；後續「是否取得學分」使用的 `passscore` 改為 `GetEffectivePassingStandard(...)`，與寫入 XML 一致。
- **再次修習 → 新增成績**：基本欄位與指定學年科目名稱後呼叫 `ApplyCourseStandards(...)`；`passscore` 改為 `GetEffectivePassingStandard(...)`。
- **重修成績 → 寫回原學期**：`passscore` 改為 `GetEffectivePassingStandard(...)`，再寫重修成績；寫回原學期時改為呼叫 `ApplyCourseStandards(...)` 更新兩標準。
- **補修成績**：先呼叫 `ApplyCourseStandards(...)`，再以 `GetEffectivePassingStandard(...)` 取得 `passscore` 做「是否取得學分」判斷。
- **一般修課 → 更新既有成績**：課程資料 #endregion 後立即呼叫 `ApplyCourseStandards(...)`；後續 `passscore` 改為 `GetEffectivePassingStandard(...)`。
- **一般修課 → 新增成績**：指定學年科目名稱後呼叫 `ApplyCourseStandards(...)`；`passscore` 改為 `GetEffectivePassingStandard(...)`。

原則：**先寫入修課及格標準與修課補考標準（ApplyCourseStandards），再進行後續成績與學分判斷**；**判斷用數值一律來自 GetEffectivePassingStandard**，避免 XML 寫入值與判斷用值不一致。不改變既有商業流程與 designate_final_score 邏輯。

## 五、測試案例（建議）

1. **一般修課、更新模式**：已有 Subject XML → 修改 `sc_attend.passing_standard` / `makeup_standard` → 重算 → 確認兩屬性已更新。
2. **一般修課、更新模式、補考標準改空**：原 XML 有修課補考標準 → DB `makeup_standard` 改空 → 重算後 XML 修課補考標準應為空，不殘留舊值。
3. **一般修課、新增模式**：無該筆 Subject → DB 有兩標準 → 重算後兩欄正確寫入。
4. **無 passing_standard、有 applyLimit**：`passing_standard` 空白、`applyLimit` 有值 → 修課及格標準為 fallback，修課補考標準依 DB 或空。
5. **重修成績**：寫回原學期後，重修成績、修課及格標準、修課補考標準皆更新。
6. **補修成績**：補修回寫後，兩標準更新，ScoreP / ReScoreP 邏輯正常。
7. **再次修習**：更新或新增 Subject 後，兩標準皆同步。

## 回報摘要

### 實際新增的 helper method

- `GetEffectivePassingStandard(...)` → 有效及格標準
- `GetEffectiveMakeupStandard(...)` → 有效補考標準（nullable）
- `SetPassingStandardAttribute(...)` → 寫入修課及格標準
- `SetMakeupStandardAttribute(...)` → 寫入修課補考標準（無值清空）
- **ApplyCourseStandards(scoreElement, studentId, key, gradeYear, studentPassScoreDict, studentMakeupScoreDict, applyLimit, decimals, mode)** → 一次寫入兩標準，各分支統一使用

### 已改成統一寫入的分支

- 再次修習（更新、新增）、重修成績寫回原學期、補修成績、一般修課（更新、新增）— 共 6 處，皆改為先呼叫 `ApplyCourseStandards(...)` 寫入兩標準，再做後續判斷。
- 所有需「是否取得學分」等判斷的 `passscore`，皆改為 `GetEffectivePassingStandard(...)`，與寫入 XML 的來源一致。

### 已移除的散落寫法

- 除 helper 內之外，已無直接 `SetAttribute("修課及格標準"` / `SetAttribute("修課補考標準"`；兩欄位僅透過 `ApplyCourseStandards` 或 `SetPassingStandardAttribute` / `SetMakeupStandardAttribute` 更新。

### 原本只在 studentFinalScoreDict 時才更新的地方

- 再次修習 → 更新：原在 `if (studentFinalScoreDict[sacRecord.StudentID].ContainsKey(sKey))` 內設定兩標準，已改為課程資料後一律寫入並移除區塊內重複設定。
- 再次修習 → 新增：同上，改為在指定學年科目名稱後統一寫入並移除區塊內重複設定。
- 一般修課 → 更新：同上，改為在 #endregion 後統一寫入並移除區塊內重複設定。
- 一般修課 → 新增：改為在指定學年科目名稱後統一寫入並移除區塊內重複設定。

## 優化紀錄（0316 優化版）

### 原始風險（優化前）

- 部分分支先做「是否取得學分」、ScoreP、ReScoreP 等判斷，之後才寫修課及格/補考標準，導致判斷用舊 XML 值、寫入為新值，結果可能不一致。
- 多處重複「passscore = 100; if (studentPassScoreDict...」與「effectivePassscore + Set*」程式碼，且寫入值與判斷用 passscore 可能不同來源。

### 修改原則

- 只做「寫入標準的統一化」，不大改商業規則、不重構整支函式。
- 修課及格標準、修課補考標準：一律先算、先寫，再做後續判斷。
- 判斷用數值統一來自 `GetEffectivePassingStandard`，避免 XML 寫入與判斷不一致。

### 效能順手優化

- **sidList 改 HashSet**：學生 ID 收集改為 `HashSet<string>` 再去重轉 `List<string>`，避免 `List.Contains` 的 O(n)；並過濾 `string.IsNullOrWhiteSpace(sr.StudentID)`。

### 效能觀察

- sidList 改為 HashSet 後，學生 ID 收集與 Contains 檢查為 O(1)，學生數多時可減少重複線性掃描。

### 後續可再優化項目

- **currentSubjectScoreList 取值**：目前常用 `foreach (SemesterSubjectScoreInfo s in currentSubjectScoreList.Keys)` 再 `if (currentSubjectScoreList[s] == key)` 做 O(n) 搜尋，可考慮建立 key → 對應 ScoreInfo 的對照以降低複雜度。
