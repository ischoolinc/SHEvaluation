# Design

## Context

本文件依 2026-11-02 最新需求更新，取代先前指定值直接覆蓋原始成績的設計。

## Goals / Non-Goals

- 再次修習新增與更新都以三個來源擇優寫入本學期原始成績。
- 封存必須早於本次計算學期，且不再只作為既有學期成績的備用來源。
- 不調整一般修課、重修、補修、產生學習歷程或資料表結構。

## Decisions

1. 本學期有效成績：可解析的 `sc_attend.designate_final_score` 優先，否則使用有值的 `sacRecord.FinalScore`，先套用既有進位。指定 0 仍有效，不能改取較高的課程成績。
2. 既有學期：沿用 `dataCompareDict`，排除本次計算學期，同科目＋級別跨筆取最高分。目前仍未額外排除未來的既有學期資料；本次時間限制僅針對封存。
3. 封存 SQL 加入 `school_year < 本次學年度 OR (school_year = 本次學年度 AND semester < 本次學期)`，依學生、學年度、學期選最後更新版本。跳過不需評分科目，同科目＋級別跨符合的封存取最高分，不再只留排序後第一筆的分數。
4. 歷史五個擇優欄位沿用原始成績、學年調整成績、擇優採計成績、補考成績、重修成績；不新增歷史修課直接指定總成績欄位。
5. 新增與更新分支都合併既有學期與封存最高分，再交由 `SetRepeatOriginalScore` 與本次有效成績取高；`ChooseOriginalScore` 不再因有指定值而略過歷史比較。其 `hasDesignate` 參數目前保留，但不影響擇優結果。
6. 共用方法在只有歷史分數時回傳歷史最高分，全部缺值時回傳空值。需評分課程若無課程總成績與有效指定，仍會在前置檢核報錯並跳過。
7. 5.3 `Score` 維持本次有效成績，`RepeatScore` 沿用獨立計算但使用合併後歷史最高分；未修改產生學習歷程後續覆寫流程。

## Risks / Trade-offs

- 歷史分數掃描仍以 0 初始化，五欄皆空白可能形成 0，沿用既有行為。
- 更新模式既有補考、重修等欄位與學分判斷未改。
- 封存現在會在既有學期資料存在時也參與比較，`fromArchive` 可能同時為真，會進入既有封存來源名冊分支；需實際資料驗證名冊結果。
- 尚未完整建置主專案，也未連接實際資料庫驗證 SQL 與新增／更新流程。

## Migration Plan

無資料庫遷移。重新計算學期科目成績後生效；回復可還原此次程式修改並重新計算。
