# Design

## Context

見 `proposal.md` 的 Why。第一版實作已讓新增與更新呼叫同一個方法，但原始成績在有指定總成績時仍與歷史取較高分。一般修課的既有寫法是：指定總成績可解析就進位後同時寫入「修課直接指定總成績」與「原始成績」。

歷史成績仍由呼叫端決定。其他學期成績先進入比較；沒有符合科目名稱加級別時才用封存成績。擇優欄位維持原始成績、學年調整成績、擇優採計成績、補考成績、重修成績。本次學期節點不進入歷史字典。

5.3 再次修習成績已由 `ResolveRetake53Score` 使用指定總成績或課程總成績。重讀成績目前讀原始成績屬性。指定總成績直接覆蓋原始成績後，這個讀法會讓重讀成績失去歷史較高分。

## Goals / Non-Goals

**Goals:**

- 有指定總成績時，原始成績等於進位後的指定值。
- 沒有指定總成績時，原始成績等於課程總成績與歷史成績的較高分。
- 5.3 重讀成績等於本次有效成績與歷史最高成績的較高分，新增與更新使用同一組結果。

**Non-Goals:**

- 不修改一般修課、重修、補修與產生學習歷程。
- 不排除未來學期，不改封存只留第一筆，不改科目空白比對。
- 不啟用 `SaveScores44()`，也不改 4.4 學期學業成績的既有比較。
- 不把歷史資料上的「修課直接指定總成績」納入歷史擇優。

## Decisions

1. **原始成績與重讀成績分成兩個結果。**
   共用方法先得到本次有效成績：指定總成績可解析就進位後採用，包含 0 與負數；否則有課程總成績就進位後採用。有指定總成績時，原始成績就是本次有效成績。沒有指定總成績時，原始成績才與歷史成績取較高分；沒有課程總成績則原始成績留空。重讀成績一律取本次有效成績與歷史成績的較高分，歷史較高才採用歷史值，相等時保留本次有效成績。
   替代方案是重讀成績繼續讀原始成績。指定 80、歷史 82 時，重讀成績會變成 80，不符合名冊要求。

2. **5.3 再次修習成績維持既有方法。**
   `Score` 與 `ScoreP` 繼續呼叫 `ResolveRetake53Score`。重讀成績與成績及格改由決策 1 的重讀結果寫入，不再讀原始成績屬性。名冊仍只在既有歷史旗標為真且不計學分不是「是」時加入。
   替代方案是讓再次修習成績也取歷史較高分。那會改變 5.3.7 代表本次修習成績的意義。

3. **指定總成績屬性沿用兩個分支現有寫法。**
   可解析時寫入進位後的指定值。無法解析時寫入空白，清掉更新模式的舊值。註記仍在學分判斷之後寫實際課程成績。

4. **產生學習歷程的覆蓋只記錄，不改程式。**
   計算成績會先寫入 5.3。產生學習歷程讀回既有 5.3 後，有效指定總成績會重寫再次修習成績，且該步驟不改重讀成績。接著只有查得到補考成績的科目會進入最大值計算，來源是再次修習成績、補考成績、原始成績。指定 80、歷史 82 時，計算得到的重讀成績是 82，原始成績是 80。若該科目另有補考成績，產生學習歷程的最大值沒有歷史 82，可能把重讀成績改成較低的結果。沒有補考成績時不會進入這段，重讀成績維持計算結果。

## Risks / Trade-offs

- [有補考時產生學習歷程覆蓋重讀成績] → 這次不改 `StudentLearningHistoryProcessor`。人工測試若要保留計算出的重讀成績，需先確認該科目沒有補考成績，或另開變更。
- [4.4 重讀成績仍讀原始成績] → `SaveScores44()` 維持註解，不會入庫。有指定總成績時，記憶體中的 4.4 重讀成績是指定值，5.3 重讀成績可能是歷史較高分。
- [未來學期與封存第一筆] → 維持既有查找，不在這次修正。
- [負數指定總成績可解析] → 原始成績可以是負數。重讀成績仍與歷史取較高分。
- [更新模式保留舊補考與重修欄位] → 不清除這些欄位，取得學分候選清單也維持兩邊原本不同的內容。

## Migration Plan

沒有資料表或欄位變更。回復方式是還原程式。已經寫入的原始成績與 5.3 留到下一次計算學期科目成績才會重算。

## Open Questions

- 產生學習歷程在有補考成績時會重算重讀成績。若業務要求兩次功能執行後重讀成績仍維持計算結果，需要另開變更，不能在這次修改已測試過的產生學習歷程。
