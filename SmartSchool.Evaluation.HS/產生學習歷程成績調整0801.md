## 5.3 重讀成績（StudentLearningHistoryProcessor.cs）處理邏輯與資料來源

### 1. 資料來源
- 透過 `GetLearningHistoryRetakeDataAsDictionary53` 方法，查詢 student_learning_history 資料表，取得 serial_no = '5.3' 且 name = '重讀成績' 的紀錄。
- 主要欄位包含：身分證號、課程代碼、重讀成績、成績及格、補考成績、補考及格、重讀註記、是否採計學分等。
- 查詢結果依學生ID分組，轉為 `Dictionary<string, List<SubjectScoreRec108>>`。

### 2. 資料比對與處理
- 取得有重讀資料的學期成績（`GetStudentScoreDataAsDictionary`）。
- 針對每位學生的重讀紀錄，與學期成績進行比對：
    - 以學生ID、科目名稱、科目級別為鍵，尋找對應的學期成績。
    - 若找到，將補考成績（ReScore）等欄位補入重讀紀錄。
    - 並依補考成績與及格標準（ScoreP）判斷補考是否及格（ReScoreP）。
    - 若無法比對或資料不齊，ReScoreP 設為 -1。
    - 【2024/08/01修正紀錄】
      - 在 `StudentLearningHistoryProcessor.cs` 進行重讀成績比對時，原本以 `dataValueRecord.SchoolYear` 及 `dataValueRecord.Semester` 作為比對條件，現已改為直接使用傳入的 `_SchoolYear` 及 `_Semester` 變數。
      - 這樣可避免因資料來源不一致導致比對失敗，確保比對邏輯與查詢條件一致。
    - 【2024/08/01修正補充】
      - 因 SubjectScoreRec108 的 SchoolYear、Semester 屬性為 string，程式比對時已將 _SchoolYear、_Semester 轉為字串（_SchoolYear.ToString()、_Semester.ToString()），避免出現型別不符錯誤（Operator '==' cannot be applied to operands of type 'string' and 'int'）。
      - 補考成績（ReScore）及格標準（ScoreP）若無資料或無法解析時，預設 ScoreP = 60。

### 3. 回寫流程
- 整理所有重讀成績資料（allReScoreData53），呼叫 `_learningHistoryDataAccess.SaveScores53` 方法，將結果回寫至資料庫。
- 若無資料則不進行回寫。

### 4. 主要程式區塊
- 360~426 行：重讀成績資料取得、比對與補考判斷。
- 2561~2585 行：重讀成績資料彙整與回寫。
- 2925~3040 行：`GetLearningHistoryRetakeDataAsDictionary53` 方法，負責查詢與組裝重讀成績資料。

### 5. 資料結構
- 使用 `SubjectScoreRec108` 類別承載重讀成績各欄位。

## 再次修習學習欄位（ReAScore、ReAScoreP）存取流程與調整建議

### 1. 目前讀取與回寫流程
- 讀取：
  - 於 `GetLearningHistoryRetakeDataAsDictionary53` 方法，從 student_learning_history 資料表讀取「再次修習成績」與「再次修習成績及格」欄位，分別存入 `SubjectScoreRec108.ReAScore`、`ReAScoreP`。
  - 這些值為資料庫原始內容。
- 回寫：
  - 在 `SaveScores53` 方法，回寫「再次修習成績」與「再次修習成績及格」時，實際寫入的是 `ssr.Score`、`ssr.ScoreP`，而非 `ReAScore`、`ReAScoreP`。
  - 若 `Score`、`ScoreP` 在流程中被其他邏輯覆蓋，則回寫時資料會被更新，無法保證與原始讀取值一致。

### 2. 問題說明
- 目前「再次修習」欄位在存取過程中，**值可能被覆蓋**，導致無法保證資料不被修改。
- 若有「再次修習成績不被修改」的需求，現行流程無法滿足。

### 3. 後續調整建議
- 回寫時應直接使用 `ReAScore`、`ReAScoreP` 的原始值，避免被 `Score`、`ScoreP` 覆蓋。
- 或於流程中明確區分「再次修習」與其他成績欄位，確保資料一致性。
- 等待確認後再進行程式碼調整。

---

### 名詞釐清與欄位對應修正
- 「再次修習」不是「重修成績」，兩者在教育意義與資料結構上不同。
- 5.3重讀成績的「再次修習成績」應對應 `Score`、`ScoreP` 欄位，而非 `ReAScore`、`ReAScoreP`。
- `ReAScore`、`ReAScoreP` 僅用於重修成績（如5.2、4.3等）。
- SaveScores53 及資料流應維持：
  - 「再次修習成績」→ `Score`
  - 「再次修習成績及格」→ `ScoreP`
- 只要資料流中不覆蓋 `Score`、`ScoreP`，即可確保資料正確。
- 若有誤用ReAScore/ReAScoreP於5.3重讀成績，應立即修正。

#### 補充：5.3 重讀成績的補考成績（ReScore）來源
- 在重讀成績（5.3）處理流程中，補考成績（ReScore）並非直接來自5.3原始資料，而是：
  - 於比對階段，根據學生ID、科目名稱、科目級別，尋找對應的學期成績資料。
  - 若找到對應學期成績，將該學期成績的 ReScore（補考成績）欄位值，填入重讀成績的 ReScore 欄位。
  - 若無對應學期成績，則不更新。
- 因此，5.3重讀成績的補考成績來源於同一學生、同一科目、同一級別的學期成績資料。
- 這樣設計是為了讓重讀成績的補考資訊與學期成績保持同步。

## 預計調整：重讀成績補考成績來源比對條件

### 1. 目前比對條件
- 只比對學生ID、科目名稱、科目級別：
  ```csharp
  // 在學期成績中尋找對應的記錄
  var matchingSemsScore = semsScoreList.FirstOrDefault(s =>
      s.StudentID == dataValueRecord.StudentID &&
      s.SubjectName == dataValueRecord.SubjectName &&
      s.SubjectLevel == dataValueRecord.SubjectLevel);
  ```
- 未比對學年度（SchoolYear）、學期（Semester），可能導致抓到非本學年度、學期的成績。

### 2. 預計調整方向
- 比對條件需再加上：
  - `matchingSemsScore.SchoolYear == dataValueRecord.SchoolYear`
  - `matchingSemsScore.Semester == dataValueRecord.Semester`
- 預計調整後：
  ```csharp
  var matchingSemsScore = semsScoreList.FirstOrDefault(s =>
      s.StudentID == dataValueRecord.StudentID &&
      s.SubjectName == dataValueRecord.SubjectName &&
      s.SubjectLevel == dataValueRecord.SubjectLevel &&
      s.SchoolYear == dataValueRecord.SchoolYear &&
      s.Semester == dataValueRecord.Semester);
  ```
- 等待確認後再進行程式碼調整。
