# 產生學習歷程預檢資料功能實作記錄

**實作日期：** 2025年1月27日  
**功能目標：** 新增從 `sc_attend`（修課紀錄）產生學習歷程預檢資料功能

---

## 功能概述

新增「產生學習歷程預檢資料」功能，從學生修課紀錄（`sc_attend`）讀取資料，寫入 `student_learning_history` 表：
- **日校**：`serial_no = 41.2`、`name = 學期成績(預檢)`、JSON schema **同 4.2**
- **進校**：`serial_no = 42.2`、`name = 學期成績(預檢)`、JSON schema **同 6.2**
- 原本 `ProcessLearningHistory(...)` 流程 **不修改、不影響**

---

## 實作內容

### 1. 新增資料來源查詢方法

**檔案：** `Process\Wizards\LearningHistory\LearningHistoryDataAccess.cs`

**方法：** `GetSCAttendCourseRows(int schoolYear, int semester, List<string> studentIds)`

**功能：**
- 從 `sc_attend` 表查詢修課學生資料
- 使用 `string.Format` 建立 SQL（需注意 SQL 注入風險，後續建議改為參數化查詢）
- 查詢條件：
  - `student.status IN (1, 2)`
  - `course.school_year = @SchoolYear`
  - `course.semester = @Semester`
- 回傳欄位包含：
  - 學生基本資料（id, name, student_number, seat_no, id_number, birthdate）
  - 班級資料（class_name, grade_year）
  - 課程資料（course_id, course_name, subject, subj_level, credit, period, score_type, school_year, semester）
  - 必修/選修、部定/校訂（以 COALESCE 處理）
  - `sc_attend.subject_code`（課程代碼）
  - `sc_attend.extensions`（擴充資料）

---

### 2. 新增處理方法

**檔案：** `Process\Wizards\LearningHistory\StudentLearningHistoryProcessor.cs`

**方法：** `ProcessLearningHistory_FromSCAttend(...)`

**功能：**
- 完全獨立於既有 `ProcessLearningHistory(...)` 方法
- 主要流程：
  1. 取得學生 ID 列表
  2. 呼叫 `GetSCAttendCourseRows(...)` 取得 DataTable
  3. 逐列轉成 `SubjectScoreRec108` DTO
  4. 驗證欄位：
     - 身分證號 `id_number`：必填（缺漏時記錄錯誤，但 `checkPass = false`，仍可寫入）
     - 科目名稱 `subject`：必填（缺漏時記錄錯誤並跳過該筆）
     - 科目級別 `subj_level`：空白或正整數（不合法時記錄錯誤，但 `checkPass = false`，仍可寫入）
     - 課程代碼 `subject_code`：必填（缺漏時記錄錯誤，但 `checkPass = false`，仍可寫入）
  5. 設定 DTO 必要欄位（確保 JSON keys 完整）
  6. 寫入資料庫：
     - 日校：呼叫 `SaveScores41_2(...)`
     - 進校：呼叫 `SaveScores42_2(...)`
- 錯誤回報：使用 `bkw.ReportProgress(percent, errorDict)` 回報錯誤

### 3. 新增資料寫入方法

**方法：**
- `SaveScores41_2(List<SubjectScoreRec108> scores, int SchoolYear, int Semester)`
- `SaveScores42_2(List<SubjectScoreRec108> scores, int SchoolYear, int Semester)`

**功能：**

  - 42.2：`serialNo="42.2"`, `name="學期成績(預檢)"`
- detail serial 前綴：
  - 41.2.x（1..20）
  - 42.2.x（1..20）
- SQL template 方法：
  - `GetSemesterScoreSqlTemplate41_2(...)`
  - `GetSemesterScoreSqlTemplate42_2(...)`

**預檢資料寫入策略：**
- **不因 CodePass=false 而略過寫入**（預檢應該能看見不可提交資料）
- 若需提示：可寫入既有欄位（如 Text / DataKey / Memo），但不新增 JSON 欄位（維持 schema 不變）

## 資料來源與欄位對應

### SQL 來源
- 主要資料表：`sc_attend`（修課紀錄）
- JOIN 表：`student`、`class`、`course`
- 關鍵欄位：`sc_attend.subject_code`（課程代碼）

### 欄位 Mapping
| DTO 欄位 | SQL 來源 | 說明 |
|---------|---------|------|
| StudentID | student.id | 學生系統編號 |
| IDNumber | student.id_number | 身分證號（必填） |
| Birthday | student.birthdate | 出生日期（轉換為民國格式） |
| CourseCode | sc_attend.subject_code | 課程代碼（必填） |
| SubjectName | course.subject | 科目名稱（必填） |
| SubjectLevel | course.subj_level | 科目級別（空白或正整數） |
| GradeYear | class.grade_year | 開課年級 |
| Credit | course.credit | 修課學分/節數 |
| SchoolYear | course.school_year | 學年度 |
| Semester | course.semester | 學期 |

### 成績欄位策略
- 預檢資料從 `sc_attend` 取得，可能沒有成績資料
- 若無成績：填空值/預設值（但 key 必須存在，以維持 JSON schema 一致）

## 驗證規則

### 必填欄位檢查
1. **身分證號** (`id_number`)：
   - 必填
   - 缺漏時：記錄錯誤，`checkPass = false`，仍可寫入（預檢資料）

2. **科目名稱** (`subject`)：
   - 必填
   - 缺漏時：記錄錯誤並跳過該筆資料

3. **課程代碼** (`subject_code`)：
   - 必填
   - 缺漏時：記錄錯誤，`checkPass = false`，仍可寫入（預檢資料）

### 科目級別驗證
- **規格：** 空白或正整數
- **合法值：** `""`（空白）、`"1"`, `"2"`, `"3"`, ...
- **不合法值：** `"0"`, `"-1"`, `"A"`, `"1.5"`, ...
- **處理：** 不合法時記錄錯誤，`checkPass = false`，仍可寫入（預檢資料）

## 已知限制與注意事項

### 1. 成績欄位空值策略
- 預檢資料從 `sc_attend` 取得，可能沒有成績
- 策略：填空值，但 JSON key 必須存在（維持 schema 一致）

### 2. CodePass 策略
- **預檢資料：** 不因 `CodePass=false` 而略過寫入
- 目的：預檢應該能看見不可提交資料
- 若需提示：可寫入既有欄位（如 Text / DataKey），但不新增 JSON 欄位

### 3. 身分證號缺漏策略
- 缺漏時：記錄錯誤，`checkPass = false`
- 仍可寫入（預檢資料），但需在錯誤清單中提示

- **待後續實作：** 在 UI 設計器中新增控制項讓使用者選擇

### 5. SQL 參數化

- **待後續改進：** 改為真正的參數化查詢
