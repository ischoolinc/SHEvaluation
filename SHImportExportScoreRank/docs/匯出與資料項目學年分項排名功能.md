## 5. Excel 欄位及欄位來源

檔案格式：`.xlsx`

| Excel 欄位 | 資料來源 | 說明 |
|---|---|---|
| 學號 | `student.student_number` | 以字串輸出，避免前導 0 遺失 |
| 班級 | `rank_override.rank_name` | 歷史班級，不可改用目前班級 |
| 座號 | `student.seat_no` | 目前座號，僅供辨識 |
| 科別 | 學生目前科別（學生科別優先，否則班級科別） | 目前科別，僅供辨識 |
| 姓名 | `student.name` | 學生姓名 |
| 學年度 | `rank_override.school_year` | 排名所屬學年度 |
| 年級 | `rank_override.grade_year` | 排名所屬年級 |
| 學年學業排名 | `rank_override.rank` | 學年學業班排名 |

`ExportStudentV2` 已調整為**不**預先插入「目前學生基本資料」欄位，全部依 `ExportableFields`／`RowData` 輸出，確保「班級」不會被目前班級覆寫，且欄位順序固定。

## 6. `rank_override` 固定查詢條件

共用 `RankOverrideConstants`：

```text
semester    = -1
item_type   = 學年/分項成績
item_name   = 學業
rank_type   = 班排名
ref_exam_id IS NULL
```

匯出排序：`ref_student_id, school_year, grade_year, id`  
資料項目排序：`school_year DESC, grade_year DESC, id DESC`

---

## 7. 班級使用 `rank_name` 的原因

`rank_override.rank_name` 儲存排名當時的歷史班級。若改輸出學生目前班級，學生升級、轉班、轉科或畢業後，歷史排名所屬班級會錯誤。

---

## 8. 座號及科別使用目前資料的限制

`rank_override` 未儲存歷史座號與歷史科別。本次匯出的「座號」「科別」取自學生目前基本資料／科別對照，僅供人工辨識。

未使用 `student_sems_history`，也未將座號或科別寫入 `extension`。

## 10. 背景載入及快速切換學生處理

- `BackgroundWorker` 非同步查詢。
- `OnPrimaryKeyChanged` → `ReloadData`／`LoadDataAsync`。
- Worker 忙碌時設定 `_isBusy = true`；完成後若仍 busy，以最新 `PrimaryKey` 重載。
- `PrimaryKey` 為空時清空畫面，不執行 SQL。
- 查詢中 `Loading = true`，完成或錯誤後必定 `Loading = false`。
- `FISCA.Features.TryRegister("SchoolYearEntryRankDetailContent", ...)` 供匯入完成後重新整理。

## 15. 尚未處理或需要後續確認的事項

1. **重複自然鍵**：匯出會輸出查到的每一筆，不做刪除、合併或挑一筆；若環境出現重複，需由資料維運處理。
2. **座號／科別歷史值**：目前僅有現行值；若未來要歷史座號／科別，需另訂資料來源，不可逕寫 `extension`。
3. **實機整合測試**：需於正式／測試校務系統載入模組後驗證權限樹、Ribbon、資料項目與 Excel。
4. **`ExportStudentV2` 客製**：本專案複本已移除「目前學生基本欄位」前置輸出，僅供本模組使用；勿與其他模組共用此複本預期行為混淆。
