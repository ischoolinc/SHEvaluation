## 4. 原本 Upsert 比對條件

```text
ref_student_id
+ school_year
+ semester = -1
+ item_type = 學年/分項成績
+ item_name = 學業
+ rank_type = 班排名
+ ref_exam_id IS NULL
```

原本 Update 欄位：

```text
grade_year、rank_name、rank
```

原本 Insert：

```text
ref_exam_id = NULL
extension = '{}'::jsonb
```

## 5. 新的唯一值條件

```text
ref_student_id
+ school_year
+ semester = -1
+ grade_year
+ item_type = 學年/分項成績
+ rank_type = 班排名
```

不包含：

```text
rank
rank_name
matrix_count
extension
item_name
ref_exam_id
```

對應 matched JOIN：

```sql
LEFT JOIN rank_override ro
    ON ro.ref_student_id = ir.ref_student_id
    AND ro.school_year = ir.school_year
    AND ro.semester = -1
    AND ro.grade_year = ir.grade_year
    AND ro.item_type = '學年/分項成績'
    AND ro.rank_type = '班排名'
```

自然鍵字串（`FindDuplicateNaturalKeys` 與匯入鍵共用）：

```csharp
BuildNaturalKey(studentID, schoolYear, gradeYear)
// => "{studentID}_{schoolYear}_{gradeYear}"
```

## 6. Update 實際更新欄位

僅更新：

```text
rank
```

不更新：

```text
ref_student_id、school_year、semester、grade_year、
item_type、ref_exam_id、item_name、rank_type、
rank_name、matrix_count、extension
```

即使匯入班級名稱與資料庫不同，也不修改 `rank_name`。

- 新增資料時寫入 `-1`。
- matched JOIN 與重複自然鍵檢查不再使用 `ro.ref_exam_id IS NULL`。
- `ref_exam_id` 不列入唯一值比對條件。

## 9. `extension` 寫入方式

```sql

```

更新既有資料時不碰 `extension`。

## 10. `matrix_count` 不寫入的處理

Insert 欄位清單不含 `matrix_count`，亦不寫入 `0`。  
Update 亦不修改 `matrix_count`。

## 11. `item_name` 實際保留方式

1. 不放入本次 Upsert 唯一值比對條件。
2. 新增時仍寫入既有固定值 `RankOverrideConstants.ItemName`（`學業`）。
3. 更新既有資料時不更新 `item_name`。
4. 未改動 `item_name` 業務常數定義。

## 12. 資料庫重複自然鍵處理方式

1. 不刪除、不合併、不任意挑一筆更新。

## 18. 修正 `extension` NOT NULL 錯誤（2026-08-06）

### 問題

新增 `rank_override` 時，`data_insert` 將 `extension` 寫入 SQL `NULL`：

```sql
matched.rank,
NULL
```

但資料庫欄位 `rank_override.extension` 具有 `NOT NULL` 限制，導致：

```text
ERROR: null value in column "extension" violates not-null constraint
```

### 修改內容

僅修改 `DAO/RankOverrideDataAccess.cs` 的 `UpsertSchoolYearEntryRanks` 中 `data_insert` 的 `extension` 新增值。

因 SQL 字串使用 `string.Format`，程式碼寫為 `'{{}}'::jsonb`，執行時展開為：

```sql
matched.rank,
'{}'::jsonb
```

其餘邏輯未改動，包含：

| 項目 | 狀態 |
|---|---|
| `semester = -1` | 保留 |
| `ref_exam_id = -1` | 保留 |
| `item_type` / `item_name` / `rank_type` 固定值 | 保留 |
| `matrix_count` 不放入 Insert（維持 NULL） | 保留 |
| 相同自然鍵只更新 `rank` | 保留 |
| 不修改 `rank_name` | 保留 |
| JSONB CTE 批次處理 | 保留 |
| 匯出與學生資料項目 | 未修改 |

## 19. 寫入 `extension` 排名資料（2026-08-11）

### 修改目標

匯入學年分項排名時，新增及更新 `rank_override.extension` 排名資料。

### 修改檔案

| 檔案 | 說明 |
|---|---|
| `DAO\RankOverrideDataAccess.cs` | `UpsertSchoolYearEntryRanks` INSERT／UPDATE 寫入 extension |
| `docs\匯入學年分項排名調整.md` | 本完成紀錄 |

未修改：

- `ImportExport\ImportSchoolYearEntryRank.cs`
- `SchoolYearEntryRankImportRecord`（不新增 Extension 屬性）
- Excel 欄位規則、學號／姓名／學年度／年級／排名驗證
- 自然鍵判斷、Insert／Update 筆數統計、Log、匯入流程

### INSERT 修改

新增資料時，`extension` 由原先 `'{}'::jsonb` 改為：

```sql
jsonb_build_array(
    jsonb_build_object(
        'extension_name', '排名資料',
        'create_time', now(),
        '建立方式', '匯入',
        '成績類型', '學年',
        '成績項目', '分項'
    )
)
```

其餘 Insert 欄位與邏輯不變。

### UPDATE 修改

更新既有資料時，維持只更新 `rank`，並另外覆寫 `extension`：

```sql
SET rank = matched.rank,
    extension = jsonb_build_array(
        jsonb_build_object(
            'extension_name', '排名資料',
            'create_time', now(),
            '建立方式', '匯入',
            '成績類型', '學年',
            '成績項目', '分項'
        )
    )
```

更新時 `create_time` 使用本次匯入的 `now()`。

### extension JSON 格式

```json
[
  {
    "extension_name": "排名資料",
    "create_time": "now()",
    "建立方式": "匯入",
    "成績類型": "學年",
    "成績項目": "分項"
  }
]
```

### 注意事項

extension 採覆寫方式（`extension = jsonb_build_array(...)`），不使用 `extension || ...` 累積，避免重新匯入產生多筆重複「排名資料」object。同一筆資料只保留最新一組。

### 驗證結果

| 項目 | 結果 |
|---|---|
| 編譯結果 | 成功（見下方） |
| 新增測試 | 待實機匯入驗證 |
| 更新測試 | 待實機重新匯入驗證 |
| extension 查詢結果 | 待實機以驗證 SQL 確認 |
| Insert／Update 筆數 | 程式統計邏輯未改動 |

驗證 SQL：

```sql
SELECT
    ro.id,
    ext->>'extension_name' AS extension_name,
    ext->>'create_time' AS create_time,
    ext->>'建立方式' AS "建立方式",
    ext->>'成績類型' AS "成績類型",
    ext->>'成績項目' AS "成績項目"
FROM rank_override ro
CROSS JOIN LATERAL
    jsonb_array_elements(
        COALESCE(ro.extension, '[]'::jsonb)
    ) AS ext
WHERE ext->>'extension_name' = '排名資料'
ORDER BY ro.id DESC;
```
