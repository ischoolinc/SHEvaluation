## 背景說明

目前 `ruleType == "重修成績"` 區塊中，重修來源分數已有優先使用 `designate_final_score` 的邏輯，但後續計算 `maxScore` 時，分數來源清單未包含：

* `修課直接指定總成績`

因此當指定總成績存在且高於其他成績時，`maxScore` 不會正確反映，進而影響：

* `是否取得學分`
* 與 `passscore` 的比較結果

---

## 修改原則

1. **只修改 `ruleType == "重修成績"` 相關區塊。**
2. **只補上 `designate_final_score` 參與 `maxScore` 比較。**
3. **不要改動既有資料流、命名、寫回欄位、名冊邏輯、ApplyCourseStandards 邏輯。**
4. **不要順手重構其他區塊。**
5. **不要修改「再次修習 / 補修成績 / 一般修課」邏輯。**

### 2. 確認指定總成績來源邏輯保留

保留目前這段邏輯，不要改變判斷流程：

```csharp
decimal sourceScore = 0m;
bool useDesignate = false;
if (studentFinalScoreDict.ContainsKey(var.StudentID) &&
    studentFinalScoreDict[var.StudentID].ContainsKey(key))
{
    DataRow dr = studentFinalScoreDict[var.StudentID][key];
    decimal designateScore;
    if (dr["designate_final_score"] != null &&
        decimal.TryParse(dr["designate_final_score"].ToString(), out designateScore))
    {
        sourceScore = GetRoundScore(designateScore, decimals, mode);
        useDesignate = true;
    }
}
if (!useDesignate)
    sourceScore = GetRoundScore(sacRecord.FinalScore, decimals, mode);
```

這段**不要改掉既有邏輯**。

在 `ruleType == "重修成績"` 內，`updateScoreElement` 已取得後，補上以下處理：

* 若本次重修來源來自 `designate_final_score`，則將其寫入：

  * `修課直接指定總成績`
* 若沒有指定總成績，則不要額外清空既有欄位，也不要影響其他欄位。

#### 建議寫法

在 `sourceScore` / `useDesignate` 判斷完成後、`maxScore` 比較前，加入類似：

```csharp
if (useDesignate)
{
    updateScoreElement.SetAttribute("修課直接指定總成績", sourceScore.ToString());
}
```

```md
# 計算學期科目重修成績調整0317

## 問題說明
當 FillSemesterSubjectCalcScore 內 ruleType == "重修成績" 時，
雖然 designate_final_score 可作為重修來源分數，
但後續 maxScore 比對未納入「修課直接指定總成績」，
造成是否取得學分判斷可能不正確。

## 修改檔案
- WearyDogComputer.cs

## 修改內容
1. 在重修成績資料流中，當 designate_final_score 有值時，寫入 XML 屬性「修課直接指定總成績」。
2. 在 ruleType == "重修成績" 的 maxScore 比對欄位中，加入「修課直接指定總成績」。
3. 其餘邏輯不變。

## 修改前
- 指定總成績可作為來源分數，但不參與 maxScore 比對。

## 修改後
- 指定總成績除了可作為來源分數，也會納入 maxScore 比對。
- 是否取得學分判斷可反映指定總成績。

## 驗收
- 有指定總成績且較高時，maxScore 應取指定總成績。
- 無指定總成績時，邏輯維持原樣。
```
